## 2. 项目背景与目标

### 2.1 背景

- 主控：STM32F103C8T6 最小系统板，HSE 8 MHz，系统时钟 72 MHz。
- 执行机构：3 台 42 步进电机，分别搭配 1 台正点原子 ATK-PD42S1 CAN 光耦版闭环驱动器。
- 通信：3 台驱动器挂在同一条 CAN 总线上，通过 1 块 SN65HVD230 收发器与 STM32 的 CAN1 相连。
- 当前工程已用 STM32CubeMX 配置 CAN1 和基础外设，但尚未配置 CAN 过滤器、尚未启动 CAN，也没有电机控制代码。

### 2.2 目标

提供一个可复用的电机驱动模块，使调用方可以：

1. 不关心 CAN 帧拆分、重组、校验和、超时和重试；
2. 用简单接口控制 3 个电机的使能、相对位置、绝对位置、速度和停止；
3. 读取位置、速度、运行状态、到位标志和堵转标志；
4. 在裸机主循环中安全使用，不引入动态内存和 RTOS 依赖；
5. 在后续整机程序中直接复用，而不必把协议细节散落在 `main.c` 中。

### 2.3 非目标

v1 不实现：

- 驱动器内部 FOC/PID 算法（由 PD42S1 完成）；
- 自动回零、限位开关逻辑；
- 多轴直线/圆弧插补；
- 力矩模式、开环模式、脉冲模式、PWM 脉宽模式；
- PID、电流、细分、波特率、地址、CAN ID 等参数的在线配置；
- FreeRTOS 任务封装；
- CAN 总线错误注入和完整诊断工具。

## 3. 术语

| 术语 | 说明 |
|---|---|
| PD42S1 | 正点原子 42 步进电机 FOC 闭环驱动器，本文指 CAN 光耦版 |
| counts | 驱动器通信位置单位；51200 counts = 电机轴 1 圈 |
| 单圈绝对定位 | 上电后可确定电机在一圈内的绝对角度，但不知道掉电前累计转了多少圈 |
| 事务（transaction） | 一次“主机发一条完整指令 + 驱动器回一条完整应答”的过程 |
| 帧（frame） | 协议层完整帧：`0xC5 ... 0x5C` |
| CAN 报文 | CAN 总线上的一个数据帧，最多 8 字节 |
| 多帧 | 一条协议帧超过 8 字节，需要拆成多个 CAN 报文 |
| ACK | 驱动器对指令的应答；不是 CAN 硬件 ACK |
| 到位 | 驱动器 `0x30` 指令返回的 in-position 标志为 1 |

## 4. 系统概述

### 4.1 硬件拓扑

```text
                    +----------------------+
                    |  STM32F103C8T6       |
                    |  CAN1: PA11 / PA12   |
                    +----------+-----------+
                               |
                        CAN_TX / CAN_RX
                               |
                    +----------v-----------+
                    |  SN65HVD230          |
                    |  3.3V CAN 收发器      |
                    +----------+-----------+
                               |
                    CAN_H / CAN_L / GND
                               |
        +----------------------+----------------------+
        |                      |                      |
+-------v--------+     +-------v--------+     +-------v--------+
| PD42S1 #1      |     | PD42S1 #2      |     | PD42S1 #3      |
| addr = 1       |     | addr = 2       |     | addr = 3       |
| 42 stepper     |     | 42 stepper     |     | 42 stepper     |
+----------------+     +----------------+     +----------------+
```

### 4.2 软件边界

```text
应用层（main.c / 整机逻辑）
        |
        |  motor.h 公共接口
        v
电机驱动模块（motor.c）
        |
        +-- 设备服务层：命令组包、状态解析、单位换算、重试策略
        |
        +-- CAN 传输层：过滤器/启动、多帧发送、应答重组、2 ms 间隔、超时
        |
        v
STM32 HAL CAN1 -> SN65HVD230 -> CAN 总线 -> PD42S1
```

模块内部不动态申请内存，所有缓冲区为静态数组。

### 6.1 主控与 CAN

| 项目 | 配置 |
|---|---|
| MCU | STM32F103C8T6，LQFP48 |
| 系统时钟 | 72 MHz（HSE 8 MHz × 9） |
| CAN 外设 | CAN1 |
| CAN_RX | PA11 |
| CAN_TX | PA12 |
| CAN 波特率 | 500 kbps |
| CAN 模式 | Normal，AutoBusOff = ENABLE，AutoRetransmission = ENABLE |
| CAN 帧类型 | 扩展帧（29-bit ID） |
| 收发器 | SN65HVD230，3.3 V |
| 当前 CubeMX 状态 | `MX_CAN_Init()` 已存在；过滤器未配置，CAN 未启动 |

### 6.2 驱动器与电机

| 项目 | 配置 |
|---|---|
| 驱动器 | ATK-PD42S1 CAN 光耦版 × 3 |
| 电机 | 42 步进电机，1.8°，200 全步/圈 |
| 驱动器供电 | 12~32 V；手册建议 24 V、3 A |
| 通信协议 | 正点原子自定义协议；MODBUS 必须失能 |
| 从机地址 | 1、2、3 |
| CAN 速率 | 500 kbps |
| 位置分辨率 | 51200 counts/圈（通信位置模式） |
| 编码器 | 单圈绝对值；多圈累计位置掉电丢失 |

### 6.3 总线接线与终端电阻

- CAN_H 接 CAN_H，CAN_L 接 CAN_L，所有节点共地。
- 使用双绞线，CAN_H/CAN_L 成对走线，分支尽量短。
- 总线两端各保留一个 120 Ω 终端电阻，中间节点不应再并联终端。
- PD42S1 每台自带 120 Ω；SN65HVD230 模块通常也带 120 Ω 或终端跳线。
- 三台驱动器 + 一个模块全部保留终端会导致终端过多，通信可能不稳定。
- 断电测量 `CAN_H` 与 `CAN_L` 之间电阻，正常应约为 **60 Ω**；明显低于 60 Ω 说明终端过多。

### 6.4 接线前检查清单

- [ ] 三台驱动器地址已通过屏幕菜单分别设为 1、2、3。
- [ ] 三台驱动器 CAN 速率均为 500 kbps。
- [ ] 三台驱动器 MODBUS 均为“失能”，使用正点原子自定义协议。
- [ ] 总线只保留两个 120 Ω 终端；断电测量约 60 Ω。
- [ ] STM32、SN65HVD230、驱动器共地。
- [ ] 驱动器 24 V 供电容量足够，极性正确。
- [ ] 电机四线 A+ / A− / B− / B+ 接线正确，未带电拔插。
- [ ] 首次上电不带机械负载，或机械机构处于安全位置。
- [ ] 准备急停/断电手段。

## 7. 协议摘要

### 7.1 协议选择

PD42S1 的 CAN 版本**只支持正点原子自定义协议，不支持 Modbus-RTU**。因此本模块只实现自定义协议。

### 7.2 协议帧格式

| 帧头 | 从机地址 | 功能码 | 指令数据 | 校验和 | 帧尾 |
|---|---|---|---|---|---|
| `0xC5` | `addr` | `code` | `data[0..N-1]` | `checksum` | `0x5C` |

- 地址范围：0 为广播；1~255 为从机地址。
- 校验和：`checksum = (0xC5 + addr + code + data 所有字节) & 0xFF`。
- 多字节整数使用**大端序**（高字节在前）。
- 32 位浮点数使用 IEEE-754 单精度，按高字节到低字节发送。
- 一条完整协议帧可能超过 8 字节，需要拆成多个 CAN 报文。

### 7.3 CAN 传输规则

| 规则 | 要求 |
|---|---|
| CAN ID | 必须为 `0x100x` 扩展帧；主机发送固定使用 `0x1000` |
| 单条协议帧 | 从 `0xC5` 到 `0x5C` 连续输出 |
| CAN 拆分 | 每 8 字节一包，最后一包 1~8 字节 |
| 指令间隔 | 两条完整指令之间至少 2 ms |
| 应答 | 驱动器回复一条完整协议帧，可能跨多个 CAN 报文 |
| 多机 | 同一时刻只允许一个从机应答；主机必须串行发指令 |
| 广播/分组 | 广播地址和分组地址不应答 |

### 7.4 位置、方向、速度、加减速度

| 项目 | 说明 |
|---|---|
| 位置单位 | 51200 counts/圈 |
| 方向 | `0` 正转，`1` 反转 |
| 绝对位置/相对位置 | 数据域为“方向 + 加减速度 + 速度 + 位置幅值” |
| 位置幅值 | `uint32_t`，按大端发送；API 的带符号 counts 在内部拆成方向和幅值 |
| 位置模式速度 | `uint16_t`，0~6000 RPM；API 实际要求 1~6000 RPM |
| 速度模式速度 | `float`，0.1~6000 RPM |
| 加减速度 | `uint8_t`，0~200；0 表示直接启动 |
| 绝对定位限制 | v1 软件限制 `abs(target_counts) <= 51200` |

### 7.5 v1 使用的功能码

| 功能 | 功能码 | 下行数据长度 | 下行总长 | 上行数据长度 | 上行总长 | v1 |
|---|---|---:|---:|---:|---:|---|
| 读取软硬件版本（Ping） | `0x20` | 0 | 5 | 3 | 8 | 是 |
| 读实时转速 | `0x29` | 0 | 5 | 3 | 8 | 是 |
| 读实时位置 | `0x2A` | 0 | 5 | 5 | 10 | 是 |
| 读运行状态 | `0x2C` | 0 | 5 | 2 | 7 | 是 |
| 读堵转标志 | `0x2D` | 0 | 5 | 2 | 7 | 是 |
| 读使能状态 | `0x2F` | 0 | 5 | 2 | 7 | 是 |
| 读到位标志 | `0x30` | 0 | 5 | 2 | 7 | 是 |
| 电机使能控制 | `0xFA` | 1 | 6 | 2 | 7 | 是 |
| 速度模式控制 | `0xF1` | 6 | 11 | 1 | 6 | 是 |
| 绝对位置模式控制 | `0xF2` | 8 | 13 | 1 | 6 | 是 |
| 相对位置模式控制 | `0xF3` | 8 | 13 | 1 | 6 | 是 |
| 立即停止（刹车） | `0xFC` | 0 | 5 | 1 | 6 | 是 |

### 7.6 驱动器错误码

| 错误码 | 含义 | 本模块映射 |
|---|---|---|
| `0x01` | 应答成功 | `MOTOR_OK` |
| `0xE1` | 帧长度不足 | `MOTOR_ERR_FRAME` |
| `0xE2` | 帧头错误 | `MOTOR_ERR_FRAME` |
| `0xE3` | 帧尾错误 | `MOTOR_ERR_FRAME` |
| `0xE4` | 校验和错误 | `MOTOR_ERR_CHECKSUM` |
| `0xE5` | 不支持的功能码 | `MOTOR_ERR_DEVICE` |
| `0xE6` | 数据不合法 | `MOTOR_ERR_DEVICE` |

原始错误码通过 `Motor_GetLastDeviceError()` 保留，便于调试。

### 7.7 运行状态编码

| 值 | 状态 |
|---:|---|
| 0 | 停止 |
| 1 | 任务完成 |
| 2 | 正在运行 |
| 3 | 过载 |
| 4 | 堵转 |
| 5 | 欠压 |

### 7.8 使能状态编码

驱动器 `0x2F` 返回值：

- `0`：电机使能；
- `1`：电机失能。

注意这是反逻辑。公共接口 `Motor_ReadEnabled()` 会转换成 `true = 使能`。

> 手册 4.3.16 的示例说明存在一处自相矛盾：正文写“0：使能、1：失能”，但示例说明把 `0x00` 写成了“失能”。`0x31` 系统参数也写“0：使能、1：失能”。本设计以正文和 `0x31` 为准，联调时用 `Motor_Enable` 后读取 `0x2F` 实测确认。

## 8. 软件架构

### 8.1 文件规划

| 文件 | 作用 |
|---|---|
| `Core/Inc/motor.h` | 公共类型、常量、API 声明 |
| `Core/Src/motor.c` | CAN 传输、协议组包/解析、设备服务、单位换算 |
| `Core/Src/main.c` | 增加初始化和默认关闭的示例（只改 USER CODE 区） |
| `CMakeLists.txt` | 增加 `motor.c` 源文件 |
| `docs/PD42S1_Motor_Driver_Requirements_Design_v1.0.md` | 本文档 |

不修改：

- `Core/Src/can.c` 中 CubeMX 生成的初始化逻辑；
- `Core/Src/stm32f1xx_it.c` 的中断框架；
- `cmake/stm32cubemx/CMakeLists.txt` 的自动生成内容。

### 8.2 分层职责

| 层 | 职责 |
|---|---|
| 应用层 | 决定什么时候使能、运动、停止；处理业务错误 |
| 设备服务层 | 构造功能码和数据域；解析状态；单位换算；决定是否重试 |
| CAN 传输层 | 过滤器、启动、发送拆分、接收重组、2 ms 间隔、超时、校验 |
| HAL | CAN1 寄存器操作、邮箱、FIFO |

### 8.3 初始化流程

1. 应用先调用 CubeMX 生成的 `MX_CAN_Init()`（已存在，500 kbps）。
2. 应用调用 `Motor_Init()`。
3. `Motor_Init()` 配置 CAN 过滤器：接收所有扩展帧，具体地址在软件层匹配。
4. `Motor_Init()` 调用 `HAL_CAN_Start()`。
5. 清空 RX FIFO 中的残留报文。
6. 标记模块已初始化。
7. **不发送使能命令，不发送运动命令。**

### 8.4 一次指令事务

1. 检查模块已初始化、`id` 合法、参数在范围内。
2. 检查距离上一条完整指令是否已满 2 ms；不足则等待。
3. 清空 RX FIFO 中的陈旧报文。
4. 组协议帧：帧头、地址、功能码、数据、校验和、帧尾。
5. 按 8 字节拆分，逐包发送；等待每包发送完成，保证顺序。
6. 轮询 RX FIFO，按 5 ms 空闲间隔判断应答帧结束。
7. 校验帧头、地址、功能码、帧尾、校验和。
8. 解析数据域；若是驱动器错误码，映射为本地错误。
9. 对允许重试的指令，在超时/总线错误时重试；相对运动不重试。
10. 返回统一状态码。

### 8.5 并发模型

- v1 为裸机、单调用者模型。
- 模块内部用一个 `busy` 标志防止重入；重入时返回 `MOTOR_ERR_BUSY`。
- 不建议在中断中调用任何公共 API。
- `Motor_WaitInPosition()` 会阻塞轮询；不要放在 ISR 中。
- 后续若使用 RTOS，需要把 `HAL_Delay` 和轮询替换为任务友好的等待方式；v1 不提供。

### 9.6 方向与符号

- `Motor_MoveRelative` / `Motor_MoveAbsolute` 接受带符号 counts。
- 内部映射：
  - `target >= 0`：方向 0，幅值 `target`；
  - `target < 0`：方向 1，幅值 `-target`。
- `int32_t` 的 `INT32_MIN` 取绝对值会溢出，直接返回 `MOTOR_ERR_PARAM`。
- `Motor_SetSpeed` 接受带符号 RPM：
  - `rpm > 0`：方向 0；
  - `rpm < 0`：方向 1，幅值 `-rpm`。

## 10. 关键行为与策略

### 10.1 指令间隔

- 两条完整指令之间至少 2 ms。
- 实现使用 3 ms 保护间隔，避免 `HAL_GetTick()` 1 ms 分辨率导致不足 2 ms。
- 间隔从上一条指令的最后一个 CAN 报文发送完成开始计时。
- 同一条指令内部的多个 CAN 报文连续发送，不插入 3 ms 间隔。

### 10.2 多帧发送

- 协议帧长度 ≤ 8 字节：一包发送。
- 协议帧长度 > 8 字节：按 8 字节拆分，最后一包为剩余长度。
- 例如 13 字节的 `0xF2` 指令拆为 8 + 5。
- 逐包等待发送完成，保证 CAN 报文顺序。
- 发送超时返回 `MOTOR_ERR_CAN`。

### 10.3 多帧接收与重组

- 接收所有扩展帧，按到达顺序追加到 RX 缓冲区。
- 每收到一包刷新“最后接收时间”。
- 当总线空闲达到 `MOTOR_RX_GAP_MS`（5 ms）且至少收到一包时，认为应答结束。
- 校验：
  - 首字节 `0xC5`；
  - 末字节 `0x5C`；
  - 地址等于目标电机；
  - 功能码等于期望值；
  - 校验和正确；
  - 总长度不小于 5。
- 任一校验失败返回对应错误，不把数据交给上层。
- 缓冲区最大 64 字节；v1 实际最长应答为 10 字节。

### 10.4 应答 ID 与匹配

- 主机发送 ID 固定 `0x1000`。
- 驱动器回传 ID 由 `0x6C` 配置，当前未确认。
- 本模块**不依赖回传 ID 唯一**：接受任意扩展帧，按报文内 `addr + code + checksum` 匹配。
- 这样即使三台驱动器都使用默认回传 ID，也能工作；前提是主机串行发指令，避免同时应答冲突。
- 若总线上存在其他扩展帧设备，应在软件层忽略不匹配的报文；v1 假设这是专用总线。

### 10.5 重试策略

| 指令 | 自动重试 | 原因 |
|---|---|---|
| `Motor_Ping`、所有读指令 | 是，1 次 | 幂等 |
| `Motor_Enable` / 失能 | 是，1 次 | 幂等 |
| `Motor_Stop` | 是，1 次 | 幂等 |
| `Motor_MoveAbsolute` | 是，1 次 | 目标相同，重复发送安全 |
| `Motor_SetSpeed` | 是，1 次 | 目标速度相同 |
| `Motor_MoveRelative` | **否** | ACK 丢失后重发会多走一段 |
| `Motor_ZeroPosition` | **否** | 电机可能已移动，重复清零会改变零点 |
| `Motor_StopAll` | 否 | 广播无应答，无法确认；由上层决定是否重发 |

重试时同样要满足 3 ms 指令间隔。

### 10.6 超时建议值

| 超时 | 值 | 说明 |
|---|---:|---|
| ACK 超时 | 50 ms | 500 kbps 下足够覆盖多帧应答和驱动器处理 |
| 应答空闲间隔 | 5 ms | 判断一帧结束 |
| 到位轮询周期 | 50 ms | 避免总线过载 |
| 默认到位超时 | 30000 ms | 调用者可覆盖 |
| 单次重试 | 1 次 | 避免总线异常时长时间阻塞 |

### 10.7 到位等待

`Motor_WaitInPosition(id, timeout_ms)` 的行为：

1. 每 50 ms 读取一次 `0x30` 到位标志。
2. 若到位为 1，返回 `MOTOR_OK`。
3. 每次轮询读取 `0x2D` 堵转标志；为 1 返回 `MOTOR_ERR_STALL`。
4. 每 5 次轮询读取一次 `0x2C` 运行状态；若为 3/4/5（过载/堵转/欠压），返回 `MOTOR_ERR_STATE`。
5. 到达总超时仍未到位，返回 `MOTOR_ERR_TIMEOUT`。
6. **超时后不自动刹车**；调用者应视安全要求调用 `Motor_Stop` 或 `Motor_StopAll`。
7. 通信连续失败两次，返回通信错误，不继续无限重试。

### 10.8 停止

- `Motor_Stop(id)`：单轴 `0xFC`，等待 ACK，幂等，可重试。
- `Motor_StopAll()`：广播地址 0 发送 `0xFC`，所有驱动器执行但不应答。
  - 返回 `MOTOR_OK` 仅表示 CAN 报文发送成功，不表示每个驱动器都已确认。
  - 广播会影响总线上所有从机，只能在专用总线使用。
- 急停优先使用 `Motor_StopAll()`，随后再逐个读取状态确认。

### 10.9 绝对定位保护

- `Motor_MoveAbsolute` 在组包前检查 `abs(target_counts) <= 51200`。
- 超出返回 `MOTOR_ERR_RANGE`，**不发送任何 CAN 报文**。
- `±51200` 是单圈绝对定位的坐标合理性保护，不是机械行程限制。
- 实际机械安全范围应由硬限位、限位开关或上层更小的软件范围保证。
- 相对运动不受该硬限制，但累计行程仍应保持在一圈以内，否则会回到多圈绝对位置不可靠的问题。

### 10.10 绝对零点

- 绝对坐标的 0 点是驱动器零点，不一定是机械零点。
- 如果两者不一致，需要在装配时对齐，或在上层加固定偏移，或在已知位置调用 `Motor_ZeroPosition()` 后重新建立坐标。
- `0xF8` 清零是否会掉电保持，手册未明确保证；v1 不依赖它跨上电保持。
- 由于三轴行程都小于 1 圈，单圈绝对位置在机械连接不打滑的前提下可跨上电使用。

### 10.11 上电安全

- `Motor_Init()` 不使能、不运动。
- 示例默认关闭，不能在上电时自动动作。
- 调用者必须显式 `Motor_Enable(..., true)` 后才允许运动。
- 建议整机上电流程：初始化 CAN → 读取状态 → 确认安全 → 使能 → 运动。

> 例外：测试构建（`MOTOR_BUILD_TESTS=ON`）会在上电 1 秒后运行 `tests/embedded/motor_validation_test.c`，逐台使能并短时旋转。生产构建默认不编译测试，`main.c` 不会自动动作。

### 10.12 CAN 错误与总线关闭

- CubeMX 已配置 `AutoBusOff = ENABLE`，硬件可自动恢复总线关闭。
- v1 不实现主动总线恢复状态机；HAL 返回错误时，API 返回 `MOTOR_ERR_CAN`。
- 若连续出现 CAN 错误，调用者应停止运动、检查接线/终端电阻/地址，再重新初始化。

### 12.3 main.c

只在 USER CODE 区增加：

1. `#include "motor.h"`
2. 测试构建时包含 `motor_validation_test.h`
3. `MX_CAN_Init()` 之后调用 `Motor_Init()`，检查返回值；失败进入 `Error_Handler()`
4. 测试构建时调用 `MotorTest_RunValidation()`；生产构建不调用

生产 `main.c` 不包含测试宏、测试全局变量或自动运动逻辑。测试构建通过 `Test` preset 使用独立的 `build/Test/`。

不修改 CubeMX 生成的 `MX_CAN_Init()` 参数。

### 12.4 CAN 中断

- v1 使用轮询接收，不启用 `HAL_CAN_ActivateNotification()`。
- `can.c` 中 NVIC 已使能 `USB_LP_CAN1_RX0_IRQn`，但没有激活 RX 中断通知，不会产生回调。
- `stm32f1xx_it.c` 中的 `HAL_CAN_IRQHandler(&hcan)` 保留不动。
- 后续如改为中断接收，需要新增 `HAL_CAN_RxFifo0MsgPendingCallback`，不在 v1 范围。

### 12.5 测试构建行为

测试源码位于 `tests/embedded/motor_validation_test.c`，仅在 `MOTOR_BUILD_TESTS=ON` 时参与构建：

1. 上电等待 1 秒。
2. 逐台测试 M1/M2/M3；每台 Ping 最多 3 次，单台失败只跳过该台，不阻塞其它电机。
3. 每台执行使能、读状态/位置、100 RPM 短时旋转、停止、失能。
4. 三台分别完成后，对测试成功的电机做 50 RPM 群组运行，再调用 `Motor_StopAll()`。
5. 共 3 轮，每轮间隔 3 秒；结束后停止并失能。

测试结果保存在 `tests/embedded/motor_validation_test.c` 的 `g_test_*` 变量中，可用 GDB 观察；具体步骤见 `tests/README.md`。

> 正数对应驱动器方向 0（手册定义为顺时针/正转）。如果实际转向相反，把测试文件中的 `MOTOR_TEST_SPEED_RPM` 和 `MOTOR_TEST_GROUP_SPEED_RPM` 改成负数后重新编译。

| T-07 | 0x2A 应答解析 | 10 字节应答解析出正确的 `int32_t` 位置 |
| T-08 | 校验和错误 | 返回 `MOTOR_ERR_CHECKSUM`，不更新位置 |
| T-09 | 地址不匹配 | 忽略错误地址，最终超时或继续等待正确应答 |
| T-10 | 绝对目标越界 | `76800` 返回 `MOTOR_ERR_RANGE`，无 CAN 发送 |

### 13.4 验收标准

## 14. 风险与待确认项

| 编号 | 风险/待确认 | 影响 | 处理 |
|---|---|---|---|
| R-01 | 三台驱动器地址仍为默认 1 | 多机通信会冲突 | 接线前用屏幕菜单逐台改为 1/2/3，并逐台 Ping 验证 |
| R-02 | 尚未接线，终端电阻未知 | 通信不稳定/无法通信 | 按 6.3/6.4 检查，断电测约 60 Ω |

## 附录 C：决策记录

| 决策 | 结论 | 原因 |
|---|---|---|
| 协议选择 | 正点原子自定义协议 | CAN 版本不支持 Modbus-RTU |
| 发送 ID | 固定 0x1000 | 手册示例和厂商例程使用该 ID |
| 应答匹配 | 按 addr/code/checksum | 回传 ID 不确定，避免依赖唯一 ID |
| 运动语义 | ACK 后返回 | 便于三轴先后下发，之后分别等待 |
| 位置单位 | counts + 圈/度 | 精度和易用性兼顾 |
| 回零 | v1 不做 | 三轴行程小于 1 圈，单圈绝对定位够用 |
| 绝对限制 | ±51200 | 防止多圈绝对目标，不是机械限位 |
| 地址配置 | 屏幕菜单 | 避免总线批量改地址导致三台同时变更 |
| 重试 | 相对运动不重试 | 防止重复走位 |
| 接收方式 | 轮询 | 裸机简单可靠，v1 不需要异步 |
| 示例 | 默认关闭 | 防止上电自动动作 |
